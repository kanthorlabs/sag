## Basis

- Aelita ran each `[tested]` case on 2026-11-25 in throwaway containers: MySQL 8.4.13 as `root`, PostgreSQL 16.15 as `postgres`.
- Parser probes used `github.com/pingcap/tidb/pkg/parser` v0.0.0-20261125023135-c09f6278debe and `github.com/pganalyze/pg_query_go/v6` v6.2.5.
- `[source]` means that Aelita read the cited file: pgx v5.13.0, MySQL 8.4 `sql/sql_parse.cc`, PostgreSQL 17 source, go-keychain v0.0.1, go-keyring v0.2.8, TiDB parser `ast/dml.go`.
- The library injection test ran on macOS 26.3.1 arm64 with Go 1.25.0.
- Claude Code facts come from `code.claude.com/docs` (MCP page and sandbox page), read on 2026-11-25.
- `[not tested]` means that no check ran. The statement comes from product documentation or from reasoning.
- Not checked: Keychain item ACL behavior, Linux Secret Service, the `modelcontextprotocol/go-sdk` API, a debugger launch on macOS.

## Findings

### Blockers

- B1 - status:OPEN - action:YES - MySQL comment forms bypass C1, C2, and C3 - The TiDB parser reads the content of `/*!99999 ... */` as SQL. MySQL 8.4 skips it as a comment. For `SELECT 1 /*!99999 + ' */ INTO OUTFILE "/var/lib/mysql-files/sag_poc.txt" /*!99999 ' */`, the parser sees one string expression, no `INTO`, and no function call. MySQL wrote the file inside `START TRANSACTION READ ONLY`. `ROLLBACK` did not remove the file. The same text with `, SLEEP(3)` ran the sleep. `/*T! ... */` gives the same parser result. The PRD does not name these comment forms. `[tested]` - fix:The executor sends only text that SAG restores from the validated AST (`Restore` in the TiDB parser). The executor never sends agent text to MySQL. SAG validates the restored text one more time. The conformance suite contains these cases. - why:An agent writes a file on the database host through all three controls. This breaks requirement 5 and G2.

- B2 - status:OPEN - action:YES - Engine lexer settings change how the engine reads a validated text - PostgreSQL with `standard_conforming_strings = off` ran `pg_sleep(2)` from `SELECT 'a\', ' , pg_sleep(2) -- '` inside a read-only transaction. `pg_query_go` sees two string literals and no function call for the same text. MySQL with `sql_mode = NO_BACKSLASH_ESCAPES` ran `SLEEP(2)` from `SELECT 'x\', SLEEP(2) -- '`. The TiDB parser sees one string literal. A server default, a database, or a role can set both values. `ANSI_QUOTES` and a client character set other than UTF-8 are in the same class `[not tested]`. `[tested]` - fix:PostgreSQL `RequestBegin` adds `SET LOCAL standard_conforming_strings = on` and `SET LOCAL client_encoding = 'UTF8'`. MySQL `RequestBegin` sets one fixed `sql_mode` and `SET NAMES utf8mb4`. The TiDB parser uses the same `sql_mode`. Both adapters send deparsed text only (see B1). The `pg_query_go` deparse output is `E'a\\'`, which is safe in both modes. - why:The parser and the engine must read the same tokens. A server setting must not decide the result of C1.

- B3 - status:OPEN - action:YES - PostgreSQL function rules are a denylist with holes - `ts_stat(text)` and `ts_rewrite(tsquery, text)` are in `pg_catalog`, have no `pg_` prefix, and run the text argument as SQL. Inside a read-only transaction, `ts_stat('SELECT pg_advisory_lock(4242)::text::tsvector')` took a session lock. The lock stayed after `ROLLBACK`. `ts_stat` also read `pg_authid`, which section 8.6 forbids. `brin_summarize_new_values` and `gin_clean_pending_list` wrote index pages in a read-only transaction. That change stayed after `ROLLBACK`. All four functions pass the rules in section 8.4. `[tested]` - fix:Section 8.4 adds a volatility gate in v1. SAG already reads `pg_proc` for each call. SAG rejects each function with `provolatile = 'v'`, except a short named list (`random`, `clock_timestamp`, `gen_random_uuid`, `timeofday`). The prefix rule and the denylist stay for stable functions. Section 14.3 removes this item from Phase 3. - why:A denylist over 3,315 built-in function entries (PostgreSQL 17 `pg_proc.dat`) fails open. With a superuser credential, the inner SQL can call `pg_terminate_backend` `[not tested]`.

- B4 - status:OPEN - action:YES - MySQL rule "built-in function of the parser" has no mechanism - The TiDB parser returns the same `FuncCallExpr` node for `my_stored_fn(1)`, `tidb_version()`, and `sleep(1)` `[tested]`. Aelita found no built-in membership API in the parser module `[source]`. The name constants of the parser include TiDB-only names. MySQL resolves an unknown name to a stored function in the default database `[not tested]`. - fix:Section 8.5 defines an explicit MySQL function allowlist that SAG owns and embeds. SAG rejects each name outside the allowlist. The denylist becomes a test list. - why:The sentence "This rejects all stored functions" depends on a set that does not exist. C2 on MySQL does not block `SET GLOBAL`, locks, or file access (see S1), so C1 is the only control for function calls.

- B5 - status:OPEN - action:YES - MySQL C2 depends on a session flag that an earlier request can clear - `SET SESSION transaction_read_only = OFF` stays after `ROLLBACK`. In the next `START TRANSACTION READ ONLY`, `CREATE TABLE` succeeded. MySQL checks the read-only flag after the implicit commit (`sql_parse.cc` line 3293). `INSERT` still failed with error 1792. `SessionGuard` runs one time for each connection, and the connection returns to the pool. `[tested]` `[source]` - fix:MySQL `RequestBegin` runs each `SessionGuard` statement again before `START TRANSACTION READ ONLY`. AC7(b) adds this two-request case. - why:One C1 failure must not turn off C2 for later requests on the same connection.

- B6 - status:OPEN - action:YES - The pgx protocol claim is wrong for `Exec` - Section 8.4 says that pgx uses the extended query protocol. `Conn.Exec` without arguments always uses the simple protocol (`conn.go` lines 524 to 527, v5.13.0). The simple protocol accepts more than one statement. A DSN can also set `default_query_exec_mode=simple_protocol` (`conn.go` line 193). `[source]` - fix:Section 8.4 states that agent-derived text goes only through `Query` or `pgconn.ExecParams` with `QueryExecModeExec`. SAG removes `default_query_exec_mode` from the DSN. The conformance suite sends `SELECT 1; DELETE FROM t` with C1 off and asserts a server error. - why:`DECLARE sag_c ... FOR <statement>` has no arguments. An implementer who follows the PRD text loses the single-statement guard of the protocol.

- B7 - status:OPEN - action:YES - macOS Keychain trust does not hold for the default Go build - A default cgo build has an ad hoc linker signature (`flags=0x20002`). It loaded a library from `DYLD_INSERT_LIBRARIES` before `main`. That code runs as the trusted `sag` binary, before `PT_DENY_ATTACH`. After `codesign --force --sign - --options runtime`, the same binary ignored the variable. `[tested]` The Keychain ACL claim in section 11.2 has no acceptance criterion `[not tested]`. - fix:The v1 build adds the hardened runtime signature step. A new AC asserts that an injected library does not load. A new AC asserts that `security find-generic-password -s sag -a <name> -w` returns no value without a prompt. - why:T2 and T3 can read each Keychain secret without a prompt. This breaks requirement 1 on macOS. Section 14.3 puts signed releases in Phase 3.

- B8 - status:OPEN - action:YES - `file:` and `env:` backends and the operator guidance contradict G1 - Section 7.5 says that credentials are never in files that SAG writes. Section 11.2 adds `file:`, and the example path in section 12.5 is inside `$SAG_HOME`. The Claude Code sandbox covers shell commands only. The Read tool ignores the sandbox `denyRead` rule `[source]`. With the guidance in section 7.6, the agent reads a `file:` DSN directly. The `env:` value also exists in the shell that starts the daemon. - fix:v1 removes `env:`. `file:` stays for headless Linux only, and section 7.6 records it as a residual risk. The guidance adds the permission deny rules `Read(~/.config/sag/**)` and `Edit(~/.config/sag/**)`. AC2 forbids a `file:` path inside `$SAG_HOME`. - why:Requirement 1 says that a credential never reaches the agent. The current guidance does not block the Read tool.

- B9 - status:OPEN - action:YES - The adapter interface cannot run an operation - `Resource` in section 13.2 has no execute method. The core has no way to send `logs.query` to a CloudWatch adapter. `ReadOnlyContract` holds SQL-only fields. Section 8.2 lists 8 fields, and section 13.2 has 5. `GET /v1/resources` returns capability names only, so the bridge cannot build the tools of a new capability. - fix:Core `Resource` gets `Execute(ctx, capability, operation string, input json.RawMessage, limits Limits) (Result, error)`. The SQL contract moves to the `sql` package as a dialect interface. The bridge builds tools from the compile-time registry. Sections 8.2 and 13.2 list the same fields. - why:Requirement 3 and G5 need a core that does not know SQL. The current interface forces a core change for the first adapter that is not SQL.

- B10 - status:OPEN - action:YES - v1 scope does not fit one day - v1 lists 13 CLI commands, 3 secret backends, 2 SQL adapters with 2 AST validators, a daemon, a bridge, and 21 acceptance criteria on 2 operating systems. B1, B2, B4, and B5 add work to the MySQL adapter. This is an estimate of Aelita, not a measurement. - fix:Aelita recommends v1 = build steps 1 to 5 and step 7 with PostgreSQL only, because the PostgreSQL parser is the server grammar. MySQL becomes v1.1. Alternative A: keep both engines and cut `InspectPrivileges`, `env:`, Linux Secret Service, column redaction, `max_cell_bytes`, `EXPLAIN`, and token expiry. The MySQL risk stays in day one. Alternative B: keep the full scope and accept more than one day. Ulrich decides. - why:Requirement 2. The build order already puts MySQL last, so the cut removes no dependency.

### Suggestions

- S1 - status:OPEN - action:YES - C2 and C3 text is stronger than the engines - Inside a MySQL read-only transaction, `SET GLOBAL max_connections`, `GET_LOCK`, and `FLUSH STATUS` succeeded. The global value and the lock stayed after `ROLLBACK`. `[tested]` PostgreSQL kept session advisory locks and index changes (see B3). Section 8.1 says that a write "never becomes durable" with C3. MySQL DDL commits implicitly, and a file write does not roll back. AC7(b) tests 4 statement types only. - fix:Sections 8.4 and 8.5 each add a table "effects that only C1 blocks". The conformance suite asserts that C1 rejects each row. Section 8.1 limits C3 to transactional writes. - why:Ulrich must know which effects depend on one control only.

- S2 - status:OPEN - action:YES - The host and user secrecy claim cannot hold - Section 7.5 promises no host, user, or DSN in tool output. `SELECT current_user, current_setting('port')` returned both values in a read-only transaction `[tested]`. The TiDB parser accepts `SELECT @@hostname` `[tested]`. Driver connect errors can also name the host and the user `[not tested]`. AC14 checks the password only. - fix:Section 7.5 limits the claim to the password and the DSN text. For a connect error, the agent gets a fixed message and the `request_id`. The full scrubbed error goes to the daemon log only. - why:A promise that one SQL statement defeats weakens the threat model.

- S3 - status:OPEN - action:YES - The credential catalog rule is incomplete - Section 8.6 lists 4 PostgreSQL relations. `pg_subscription`, `pg_settings`, `pg_file_settings`, and `current_setting('primary_conninfo')` can also show passwords to a superuser `[not tested]`. On MySQL, a DSN with default database `mysql` makes `SELECT * FROM user` valid without a schema name `[not tested]`. - fix:Section 8.6 adds those relations and `current_setting`. The MySQL rule compares schema names without case. MySQL `Preflight` refuses a DSN with default database `mysql`. - why:Section 8.6 promises that stored credentials of other systems stay hidden.

- S4 - status:OPEN - action:YES - pgx merges the process environment into the connection - `pgconn.ParseConfig` reads `PGSSLROOTCERT`, `PGSSLMODE`, `PGPORT`, `PGSERVICEFILE`, `PGPASSFILE`, `PGOPTIONS`, and 19 more variables (`pgconn/config.go`, v5.13.0) `[source]`. T2 can start `sag serve` with these variables. Section 7.5 accepts `sslmode=require` or `sslmode=prefer` in a DSN without a warning. - fix:The daemon removes each `PG*` variable at start and sets each connection field from the secret. The daemon refuses a TLS mode weaker than `verify-full`, except for a loopback host or a Unix socket. - why:With an attacker CA or unverified TLS, a false server can ask the driver for the password `[not tested]`.

- S5 - status:OPEN - action:YES - Agent tokens are readable by each process of the same OS user - `claude mcp add --env SAG_TOKEN=<token>` stores the token as plain text in `~/.claude.json`. `--scope project` puts it in `.mcp.json`, which the docs tell the user to commit `[source]`. A T2 agent can read the token of another agent and call the socket. - fix:Section 7.6 adds residual risk R6: tokens separate agents only against T1. The guidance forbids `--scope project` and adds the deny rule `Read(~/.claude.json)`. - why:G3 claims a separate identity for each agent. In v1 this holds only for an agent without shell or file access.

- S6 - status:OPEN - action:YES - The validator must allowlist fields, not node types only - `SelectStmt.Accept` in the TiDB parser does not visit `SelectIntoOpt`. It visits only the tables of `LockInfo` (`ast/dml.go`) `[source]`. The parser drops the unknown hint `NO_ICP` with a warning, so the AST shows no hint `[tested]`. - fix:For each allowed node type, the allowlist names each permitted field. A non-zero field outside the list rejects the statement. The walk uses reflection for the TiDB AST and `protoreflect` for pg_query, not `Accept`. - why:A visitor that skips a field hides that field from C1. The fail-closed rule in section 8.3 covers node types only.

- S7 - status:OPEN - action:YES - The operator rule rejects databases with common extensions - Section 8.4 rejects a name that has any match outside `pg_catalog`. Extensions such as `citext`, `hstore`, `pgvector`, and PostGIS define operators such as `=` and `<->` in their own schema `[not tested]`. Each query with `=` then fails on such a database. - fix:Aelita recommends: keep the rule in v1, and `Preflight` reports each name that collides. Alternative: a `sag.yaml` list of trusted extensions. This adds one key and one trust decision. Ulrich decides. - why:The rule is safe, but SAG can be unusable on a real database. Ulrich needs this fact before the build.

- S8 - status:OPEN - action:YES - Static validation runs after `RequestBegin` - Section 13.3 starts a transaction before `Validator.Validate`. A statement that the parser rejects still takes a pooled connection and several round trips. - fix:Validation has two phases. The parse and the allowlist walk run before step 4, without a connection. The catalog lookup runs inside the transaction. - why:A denied request must not reach the database. AC7(a) can then run as a unit test without a container.

- S9 - status:OPEN - action:YES - Audit failure behavior is not defined - Section 9.5 does not say what the daemon does when the audit append fails. Step 7 writes the record after execution. T2 and T3 can edit or delete audit files, and section 7.6 does not list this risk. - fix:Section 9.5 states that the daemon returns `internal` and no data when the audit append fails. R1 adds audit change and deletion by T2 and T3. - why:G4 requires one audit record for each request.

- S10 - status:OPEN - action:YES - R5 names views only - A user cast, a domain check, a row-level security policy, and a `file_fdw` foreign table with a `program` option also run code that the validator cannot see `[not tested]`. - fix:R5 lists these object types. PostgreSQL `Preflight` adds `file_fdw` to the refused extensions. - why:The residual risk must name each path that C1 does not cover.

- S11 - status:OPEN - action:YES - Some acceptance criteria are not verifiable as written - AC3 checks help text, which proves nothing about output. AC10 needs a slow statement, but C1 rejects each sleep function. AC7 needs a "test build" with a control off. The peer check in AC12 needs a second OS user. AC2 on Linux needs a Secret Service session. - fix:AC3: run each command with a stored secret and search stdout and stderr for the value. AC10: a second session holds a table lock. AC7: tests inject a pass-through validator, and no build flag exists. Mark the AC12 peer check and Linux AC2 as manual. - why:Each AC needs one executable check. A build flag that turns off a control is a risk.

- S12 - status:OPEN - action:YES - The build order omits verification for three criteria - No step in section 14.1 verifies AC4, AC5, or AC21 for PostgreSQL. Step 6 lists them for MySQL only. - fix:Step 3 adds AC5 and AC21. Step 4 adds AC4, or v1 removes AC4 together with `InspectPrivileges`. - why:The rule "do not start a step before the verify check passes" needs each AC in one step.

- S13 - status:OPEN - action:YES - Default result limits exceed the Claude Code MCP limit - `max_result_bytes` is 1 MiB, and section 12.3 returns the JSON two times. Claude Code allows 25,000 tokens by default and moves text over 50,000 characters to a file `[source]`. - fix:The default `max_result_bytes` becomes 32 KiB and the default `max_rows` becomes 100. Ulrich confirms the values in Q11. - why:The client cuts or redirects a default-size result, and the query cost is lost.

- S14 - status:OPEN - action:YES - Dependency and version claims need correction - The latest TiDB parser requires Go 1.27.3, and the probe build changed to that toolchain `[tested]`. go.dev lists 1.27.4 and 1.26.11 as the current releases on 2026-11-25. `gopkg.in/yaml.v3` is archived, and its last release is 2022-05-27 `[source]`. The TiDB parser module has no tagged version. `pg_query_go` v6.2.5 embeds the PostgreSQL 17.7 grammar, and no v7 exists. - fix:Section 5 sets Go 1.27, replaces the YAML library with `go.yaml.in/yaml/v3`, and pins one TiDB parser commit. Section 13.5 states that SAG rejects syntax that is new in PostgreSQL 18. - why:"Go 1.25 or later" does not build the MySQL adapter with the latest parser.

- S15 - status:OPEN - action:YES - `EXPLAIN` options need an allowlist - `EXPLAIN (ANALYZE true, FORMAT json)` arrives as an option list, not as a keyword `[tested]`. Section 8.3 says "without `ANALYZE`" only. - fix:Section 8.3 allows the options `FORMAT`, `VERBOSE`, and `COSTS` only. SAG rejects each other option name. - why:A parser upgrade can add an option that executes the statement.

- S16 - status:OPEN - action:YES - Result shape and limits are SQL-shaped - The post-execute hooks cap cells and redact by column name. `Limits` has `max_rows` and `statement_timeout`. A CloudWatch query needs a time range limit and a scanned-bytes limit. - fix:Section 13 states that each capability returns the tabular `Result` (`columns`, `rows`). Limits that only one adapter needs live in the input schema of that adapter. - why:The hooks stay generic, and a new adapter does not change `Limits`.

- S17 - status:OPEN - action:YES - Timeout values are not defined - Section 8.4 sets `lock_timeout` and `idle_in_transaction_session_timeout`. Section 9.1 gives no value for them. - fix:Section 9.1 adds one row for each value. - why:The implementer must not choose a limit.

- S18 - status:OPEN - action:YES - Agent lifecycle is not defined - The PRD does not say if `sag agent create <name>` needs an agent entry in `sag.yaml`. The daemon reloads `tokens.json` on change, but a change of `sag.yaml` needs a restart until Phase 2. - fix:Section 10.1 states that `sag agent create` fails for a name that is not in `sag.yaml`. Section 6 states that a grant change needs a daemon restart in v1. - why:Two files hold agent names, and they can disagree.

- S19 - status:OPEN - action:YES - Secret CLI behavior for `file:` is not defined - Section 12.1 says that `sag secret set` uses "the default backend for the OS". The PRD does not define that backend on headless Linux. The mode table in section 6 has no row for a secrets directory. - fix:Section 11 states the backend choice rule and the path and mode of file secrets. - why:The implementer must not choose where a credential is stored.

- S20 - status:OPEN - action:YES - Three items add work and give no guarantee - `InspectPrivileges` at daemon start changes no behavior. The plaintext key rule in section 11.1 repeats the unknown-key rule in section 12.5. The memory zero note in section 5 cannot hold, because each driver keeps the password for the pool. - fix:v1 removes `InspectPrivileges` from daemon start, removes the key-name rule, and removes the memory zero note. - why:Simplicity first. Each item costs build time in a one-day scope.

- S21 - status:OPEN - action:YES - Two section references are wrong - Section 3 and section 7.5 cite section 8.5 for credential catalogs. The credential catalog rule is section 8.6. - fix:Change both references to section 8.6. - why:Section 8.5 is the MySQL mechanism.

- S22 - status:OPEN - action:NO - Daemon and bridge split in v1 - Aelita considered one stdio process that holds the credentials, without a daemon, a socket, or tokens. That design has fewer parts. - fix:No change. - why:Keychain trust binds to one long-lived process. The Phase 2 SDK and the Phase 3 dedicated OS user both need the socket API.

- S23 - status:OPEN - action:NO - PostgreSQL read-only transaction cannot change to read-write - `check_transaction_read_only` rejects the change after the first snapshot of the transaction (`variable.c` lines 544 to 572, PostgreSQL 17) `[source]`. The catalog lookup of SAG takes that snapshot before the agent text runs. - fix:No change. - why:`set_config` and a function-level `SET` cannot turn off C2 on PostgreSQL.

- S24 - status:OPEN - action:NO - MySQL temporary tables in a read-only transaction - `CREATE TEMPORARY TABLE` failed with error 1792 when the session flag was on `[tested]`. The MySQL manual permits DML on a temporary table that exists `[not tested]`. No request can create one. - fix:No change after B5. - why:C1 and C2 both block the creation of a temporary table.

- S25 - status:OPEN - action:NO - Library claims that hold - `pg_query_go/v6` exists and embeds the PostgreSQL server grammar. `github.com/pingcap/tidb/pkg/parser` is a separate module. `keybase/go-keychain` calls the Security framework through cgo. `zalando/go-keyring` uses D-Bus on Linux. `modelcontextprotocol/go-sdk` v1.8.0, `pgx` v5.13.0, and `go-sql-driver/mysql` v1.10.2 exist. `[source]` - fix:No change. - why:These claims in section 5 are correct. `go-keyring` starts `/usr/bin/security` on macOS, so SAG must use it on Linux only, as the PRD says.

## Verdict

The PRD is not ready for an implementation plan today. B1 to B6 show that the read-only guarantee fails on both engines with a write-capable credential. B7 and B8 show that a credential can reach a same-user agent. B9 and B10 need one design decision and one scope decision from Ulrich. No blocker needs a new architecture. Each fix is a rule change or a scope cut inside the current design. After Ulrich accepts the fixes for B1 to B10, the PRD is ready for an implementation plan. The suggestions S1 to S21 can go into the same PRD revision.
