Podman mounts `/run/secrets` into the container, so `ac01-valid.yaml` also exits 1 there (`lstat /run/secrets/sag-orders: no such file or directory`). The unit tests in `internal/cli/config_check_test.go:31-54` discriminate; the e2e test does not. - fix:For each invalid fixture, assert the cause in stderr (the config key path of that fixture) and assert that stderr contains no `/run/secrets` text. Add an in-image control: run `ac01-valid.yaml` with its secrets mounted with `uid=65532,mode=0400`, and expect exit 0 and `config ok`. - why:The AC report shows AC01 `PASS` from four cases that pass for every input. The gate evidence must fail when the behavior is wrong.

- B2 - status:OPEN - action:YES - Config errors print a DSN with its password - [tested] `sag config check` prints the full DSN when the DSN is the value of `kind` (`internal/cli/config_check.go:47`), an unknown key or a duplicate key (`internal/config/config.go:145`), or a resource name (`internal/config/config.go:230-232`). [read] `sag serve` prints the same text to the container log (`internal/daemon/resources.go:22`, `internal/config/config.go:145`). `yamlValuePattern` masks only text between backticks. - fix:Print no operator text in config errors. Validate `kind` against `namePattern` in `internal/config` and print a fixed message. Replace each YAML decode error with its line number and a fixed class (`unknown key`, `duplicate key`, `wrong type`). Print a resource name only after it matches `namePattern`. Add the four cases next to `TestTypeErrorHidesValue`. - why:PRD section 10.2 states that SAG never puts a DSN string into an error or a log line. Asset A1 has the highest priority. The exposure needs an operator edit error, but the container log then keeps the password.

- S1 - status:OPEN - action:YES - Preflight has no deadline after connect - [tested] A server that completes authentication and then sends no data blocks `Preflight` without limit (`internal/adapter/postgres/preflight.go:34-39`). Aelita stopped the probe after 20 s; `connect_timeout` is 5 s. `openResources` runs each preflight in sequence before the listener opens (`internal/daemon/resources.go:46`, `internal/daemon/run.go:73`). One stalled database stops `sag serve` with no log line and no `/healthz`. - fix:In `daemon.preflight`, wrap the call in `context.WithTimeout` (for example `connect_timeout` plus 10 s). Close the connection with a bounded context. Add a unit test with a stalled fake server (`pgproto3.Backend`). - why:Actor T5 or a network fault controls the availability of the daemon for all resources. PRD section 11.3 expects a failed resource to become `resource_unavailable`, not to stop the other resources.

- S2 - status:OPEN - action:YES - `conn.Exec` without arguments uses the simple protocol - [tested] With the layer-1 config (`DefaultQueryExecMode = QueryExecModeExec`, `internal/adapter/postgres/connconfig.go:59`), `conn.Exec` with the text `CREATE TEMP TABLE ...; INSERT ...; SELECT 1` succeeds and writes one row. pgx v5.13.0 forces the simple protocol when `Exec` has no arguments (pgx `conn.go:524-527`). `conn.Query` with two statements fails with SQLSTATE `42601`. `readVersion` uses `conn.Exec` (`internal/adapter/postgres/preflight.go:34`, `:39`). `TestExecModeExec` (`connconfig_test.go:107-112`) asserts only the config field. - fix:Send `BEGIN` and `ROLLBACK` through `conn.PgConn().ExecParams` or `conn.Query`. Add an integration test: multi-statement text through the adapter connection path returns `42601`. Record the rule "no `conn.Exec` without arguments" in the T2.0 contract. - why:C2 and AC6 in layer 2 depend on the extended protocol. The current test gives false confidence, and layer 2 builds on the layer-1 pattern.

- S3 - status:OPEN - action:YES - Unauthenticated redirect for non-canonical paths - [tested] `GET //mcp`, `POST //mcp`, `GET /a/../mcp`, and `GET //healthz` without a token return `307` with a `Location` header, not `401`. The `sag:e2e` container gives the same result. `ServeMux` cleans the path before `authenticate` runs (`internal/endpoint/server.go:58-66`). - fix:Put `authenticate` outside the mux. One outer handler serves `GET /healthz` on the exact path and sends each other request to `authenticate` first. Add the paths to `Test401HasWWWAuthenticate`. - why:PRD section 6 states that all paths other than `/healthz` need a JWT, and each failure returns `401`. In layer 4, these requests also write no audit record for the authentication failure.

- S4 - status:OPEN - action:YES - Endpoint has no idle timeout, body timeout, or header size limit - [tested] After one `401`, an unauthenticated connection stays open and usable after 12 s without traffic. A request with a valid JWT and a partial body holds its handler for more than 12 s. [read] `http.Server` sets only `ReadHeaderTimeout` (`internal/endpoint/server.go:95-105`). `MaxHeaderBytes` is the 1 MiB default, and `token.Verify` decodes a header of that size before the signature check. - fix:Set `IdleTimeout` (for example 60 s), `ReadTimeout` (for example 10 s), and `MaxHeaderBytes` (for example 16 KiB). Add the values to `TestServerTimeouts`. - why:Actor T2 reaches the port without a JWT and holds file descriptors without limit. PRD section 7.5 names the timeouts as a T2 mitigation, and rate limits come only in phase 2.

- S5 - status:OPEN - action:YES - `.dev/` is not in `.gitignore` - [read] `scripts/dev-up.sh:5-26` writes `master-key`, `pg-password`, and TLS keys to `.dev/local/dev`. - S6 - status:OPEN - action:YES - Base images use tags, not digests - [read] `deploy/Containerfile:1` and `deploy/Containerfile:16` name `golang:1.27.4-bookworm` and `gcr.io/distroless/base-debian12:nonroot`. ## Checks without a finding

- Code comments: none in Go, shell, YAML, `Makefile`, and `Containerfile`. Only `//go:build` lines exist.
- Repository content: no private key, no real JWT, no real DSN. The DSN and JWT literals are test dummies. `scripts/dev-up.sh:35` holds a `printf` template, not a password.
- AC report: it holds statuses only and no credential.
- Daemon log of the e2e container [tested]: no master key, no database password, no DSN text, no JWT.
- Image [tested]: user `65532:65532`, `/var/lib/sag`, `audit`, and `approvals` with mode 0700 and owner 65532, binary with owner root and mode 0755, no shell, no busybox.
- Harness container flags [tested]: read-only root filesystem, `--cap-drop=all`, `no-new-privileges`, publish on `127.0.0.1`.
- JWT [tested]: `alg` values `none`, `HS512`, and `hs256` fail. Unknown, absent, and wrong-type claims fail in the PRD order. The `401` has an empty body and `WWW-Authenticate: Bearer`. The signature compare uses `hmac.Equal`.
- Secrets [read, unit tests pass]: `O_NOFOLLOW` open, then `fstat` on the same descriptor, so no TOCTOU exists. The loader checks owner, mode 0400, regular file, and a name without a path separator.
- PostgreSQL connection config [tested]: query parameters, fragments, and multiple hosts fail. The error text never contains the URL. `Fallbacks` is empty. The TLS exemption applies to loopback IP literals only; `localhost` gets `verify-full`.
- Inventory [tested in the container]: an agent sees only its served resources. A resource with a failed preflight, a resource of a different agent, and a resource without agents stay hidden.
